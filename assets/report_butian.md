# 补天 · 漏洞提交模板（13 字段）

> 平台：补天漏洞响应平台
> 用途：L6 提交报告的格式依据
> 通用判定规则见 `SKILL.md §4 判定标准`

## 一、字段规格

| # | 字段 | 约束 |
|---|---|---|
| 1 | 厂商名称 | 目标单位**全称** |
| 2 | 域名或 ip | 标准主域名。**不要**带 `https://`，不要带路径 |
| 3 | 漏洞类别 | 固定 `Web漏洞` |
| 4 | 漏洞标题 | `单位名称 + 漏洞具体类型` |
| 5 | 漏洞URL | **必须** `http(s)://` 开头，指向最小复现入口 |
| 6 | 漏洞类型 | 固定 `事件型` |
| 7 | 漏洞具体类型 | 从下方枚举**单选** |
| 8 | 漏洞等级 | `低` / `中` / `高` / `严重`，见第四节映射 |
| 9 | 简要描述 | 概况 + 影响。**不写**参数名 / payload / 路径细节，见第五节措辞约束 |
| 10 | 详细细节 | **用 Kali 与 Burp 复现的具体步骤**，写法见第八节 |
| 11 | 修复方案 | 具体可操作：改什么、怎么改、验收标准 |
| 12 | 所属行业 | 从下方枚举**单选** |
| 13 | 所属地区 | 省 / 市 / 区 三级 |

## 四、字段 8 · CVSS 3.1 基础分 → 平台等级

| CVSS 3.1 | 平台等级 |
|---|---|
| 9.0–10.0 | **严重** |
| 7.0–8.9 | **高** |
| 4.0–6.9 | **中** |
| 0.1–3.9 | **低** |
| 0.0 | 不提交 |

**背离修正**：CVSS 低估而影响分级为 `I1` / `I2` 时（见 `SKILL.md §4` 配合表），
字段 8 可**上调一段**，但必须在字段 9 / 10 写明业务影响理由。

## 五、提交前置门禁

| 条件 | 不满足时 |
|---|---|
| 影响分级 ∈ `I1` / `I2`（`I3` 视条件依赖） | 不提交（`I4` 只能作链组件） |
| 可复现，有证据 | 不提交 |
| 泄露 / 越权类已过信息公开性核验（`SKILL.md §4 L5.1`） | 不提交 |
| `publicness ∈ {public, unknown}` | **不得**定级 ≥ 高，不得提交 |
| 13 字段全部填写且合规 | 不提交 |

**措辞约束（字段 9）**：`publicness != private` 时，**禁用**
"机密 / 内部数据 / 绕过付费 / 未授权获取数据" 等措辞。

> **铁律**：「未授权」≠「非公开」。先证明信息本非公开，再谈泄露。

## 八、字段 10 · 复现步骤写法

**必须写成「用 Kali 和 Burp 怎么复现」的具体操作**，逐步编号，第三方照着做能独立复现。

```markdown
10. 详细细节：

【环境】
  Kali：<IP / 版本>
  Burp：<版本>，代理 <host:port>

【步骤】
  1. Kali —— <做什么>
     命令：
       <可直接复制的完整命令>
     观察：
       <期望输出>

  2. Burp Repeater —— <做什么>
     请求：
       <完整原始请求>
     响应：
       <关键响应片段>

【结果】
  <最终证明了什么影响>
```

**要求**

- **Kali 部分由 agent 执行**（经 `kali` MCP），命令必须实际跑通、结果必须实际观察到
- **Burp 部分由人类操作** —— agent 只负责**描述步骤并给出完整请求**，不声称自己在 Burp 里验证过
- 每步给出**可直接复制**的命令或完整请求
- Burp 部分写明是 `Repeater` / `Intruder` / `Scanner`，以及关键设置（如 payload 位置）
- 不出现"见上文""同上"这类指代
- 敏感数据部分打码，保留可验证性
- **只证明影响，不扩大影响**（不拖库、不批量下载、不删改）
